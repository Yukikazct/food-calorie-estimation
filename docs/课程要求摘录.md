# 第02题与统一课程要求

来源：根目录原始课程要求Word文档。以下保留相关原文。

《神经网络与深度学习》课程大作业16 个可选选题

一、统一要求

16 个选题任选 1 个。公开数据集为主，须写明数据来源和划分。

至少训练或微调一个神经网络模块；不能仅调用在线 API、仅运行预训练模型推理或仅制作网页界面。

完成基线与改进对比：例如冻结分类头训练 vs 部分骨干微调，或单模态 vs 多模态。必须控制主要变量。

报告 Accuracy/F1/mAP/IoU 等适合任务的指标，并统计 Params、MACs 或 FLOPs（注明口径）及推理耗时或显存。

优先使用官方 train/validation/test 划分；避免同一人、同一视频、同一场景的样本同时进入训练和测试。

最终提交完整代码、实验结果表、训练曲线和 1 个简短演示视频或截图；最终需提交英文 IEEE 格式课程论文。

需遵守数据集许可；涉及人脸、摄像头、语音等个人数据，必须征得同意，不得用于未经授权的监控或医学诊断。

二、选题清单

02｜校园食堂菜品识别与热量区间估算

视觉·分类  ·  难度：中等

应用场景：拍照识别菜品，结合份量信息显示粗略热量范围。

公开数据集：Food-101；可选 ChineseFood172（需自行确认获取与许可）；补充食堂图像。https://docs.pytorch.org/vision/main/generated/torchvision.datasets.Food101.html

推荐模型：ResNet18、EfficientNet-B0、MobileNetV3

可以完成：选 10–20 类；预训练分类头训练后解冻最后一层微调；测试食堂实拍集。

对比实验：冻结 vs 解冻；公开测试集 vs 食堂图像；颜色增强前后。

评价指标：Accuracy、Macro-F1、混淆矩阵、跨域性能、推理耗时。

最终展示：照片 → Top-3 菜品及热量区间。

三、课程报告要求

根据所选 Project，完成实际的模型训练、微调与评估，并撰写一篇英文研究型课程论文（Course Project Report）。报告需包含 Title、Abstract、Keywords、正文及 References。

（一）论文正文结构

1. Introduction：介绍研究背景、任务定义、研究动机、相关工作的局限，以及本项目拟解决的问题与主要工作。

2. Dataset：介绍公开数据集的来源、规模、类别分布、数据预处理和训练/验证/测试集划分。涉及自建数据时，说明采集、标注、质量控制和数据泄漏防范措施。

3. Method：说明任务建模、所采用的网络架构、预训练模型、微调策略、损失函数和训练流程。鼓励使用结构图、流程图或必要的数学公式。

4. Experiments：包括 Experimental Setup（硬件、Epochs、Batch Size、Learning Rate、Optimizer、指标等）、Experimental Results（真实定量结果）、Comparative Experiments（至少一组公平对比）、Visualization（代码产生的可视化）和 Analysis（结果解释、失败案例及局限）。

5. Conclusion：总结项目完成情况、主要实验发现、现有局限与可能的改进方向。

（二）论文格式

必须使用英文撰写，严格参考 IEEE Conference Template（LaTeX）排版，正文建议控制在 6–9 页。论文应规范设置图表、公式、章节和参考文献，不得擅自修改模板规定的版式。

官方模板：https://www.overleaf.com/latex/templates/ieee-conference-template/grfzhhncsfqn

（三）学术规范与实验真实性

1. 必须包含实际训练或微调及实验验证；不接受纯综述、纯讨论或仅调用现成模型/API 完成推理的项目。

2. 所有定量结果、表格、训练曲线和预测示例必须来自真实代码运行，严禁编造、篡改或虚构实验数据。

3. 实验性可视化（如训练曲线、混淆矩阵、特征图、检测框、分割图）必须由代码或真实实验数据生成，不得使用 AI 图像生成工具伪造实验结果。

4. 至少完成2组有意义的对比实验，明确控制变量，并在报告中解释结果差异。

5. 代码与结果应可复现；Jupyter Notebook 必须保留关键运行输出，说明依赖、配置、数据获取与运行步骤。

6. 规范引用所使用的预训练模型、公开数据集、相关论文及第三方代码，不得将他人成果表述为原创。

四、统一提交材料

1. 英文课程论文：PDF 格式，采用 IEEE Conference Template（LaTeX），正文建议 6–9 页。

2. 完整代码：提交 .ipynb 或 .py 文件、依赖与运行说明；Notebook 应保留训练、评估及可视化的关键运行输出。

3. 数据与实验结果：说明数据来源及划分；提供基线与微调对比、至少一组对比实验、训练曲线和真实预测案例。

4. 模型复杂度：统计 Params、MACs/FLOPs（注明输入尺寸及统计口径）和推理耗时或 FPS（按项目适用情况）。

5. 项目演示：提供 2–5 分钟演示视频或现场演示，展示模型在未参与训练的新样本上的预测效果。

特别说明：不以绝对准确率高低作为唯一评分标准；优先评价任务完成度、任务难度、训练真实性、实验公平性、结果可信度与独立实现程度。

选题确定后，应先完成“数据可用性检查＋预训练模型单次推理＋显存测试”，再启动正式训练。自行调整，挑战和客服挑战的方案可在报告中阐述。
