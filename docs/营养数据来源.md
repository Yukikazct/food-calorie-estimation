# 营养参考数据与估算口径

更新日期：2026-11-10。`data/nutrition.json`中的数值来自本轮实际访问的 **USDA FoodData Central API**，包括SR Legacy与Survey (FNDDS)条目。每条参考均保留FDC ID、英文食品描述、数据类型、发布日期、Energy营养素编号1008、单位KCAL、证据摘录文件SHA-256与官方页面链接。

图像分类只提出菜品候选。用户需要确认菜品并输入**可食部分克数**，然后按公式换算：

`热量（kcal）＝每100g参考热量 × 输入克数 / 100`。

重量不是由照片估计，营养值也不是从图像模型输出计算出来的。

例如，选择热狗并输入150g，页面返回406.5–444 kcal；这来自四种已列热狗配方按同一重量换算。煎饺目前只有一个相近复合类别参考，100g返回192 kcal，**不会人为加减百分比制造区间**。煎饺和肉酱面均明确记录了近似类别映射，不能将其写成对某个具体配方的精确测量。

## 来源与选择记录

- [USDA FoodData Central](https://fdc.nal.usda.gov/)
- [FoodData Central API Guide](https://fdc.nal.usda.gov/api-guide)
- [FoodData Central Data Documentation](https://fdc.nal.usda.gov/data-documentation.html)

查询使用官方API允许的公开演示访问方式，不使用个人凭据或付费接口，也没有上传用户图片或个人数据。运行时完全读取本地JSON，不依赖在线API。

可随仓库分发的最小证据保存在`data/nutrition_sources/`，无需依赖被忽略的`runs/`目录，也不需要API凭据：

- `usda_energy_records.json`：34个被引用食品的FDC ID、描述、数据类型、发布日期及Energy原始字段摘录。所有保留字段与官方响应一致，只省略未使用食品和其他营养素；这是**字段摘录，并非完整HTTP响应**。原完整响应的SHA-256另存于各条目的`original_response_sha256`。
- `usda_detail_crosscheck.json`：通过独立食品详情请求取得的4条能量字段摘录，涵盖薯条、完整热狗、煎饺近似条目和加州寿司卷，与搜索接口的数值一致。
- `verify_sources.py`与`verification.json`：可独立运行的核验脚本和实际核验结果，检查全部34条记录的证据文件哈希、FDC ID、描述、发布日期、单位、能量值及上下界，并检查4条详情记录一致性。它复核本地证据与营养表的一致性，不冒充实时重新访问USDA或鉴定来源真实性。

使用指定环境复核：`.venv-sitting-posture/bin/python data/nutrition_sources/verify_sources.py`。上述文件仅包含本项目实际采用的食品记录，无访问凭据、个人路径或无关完整搜索响应。热狗采用完整三明治条目，未用单独香肠或面包替代。

USDA署名与每个食品条目的官方链接已保留。**本轮FDC网页文档/条款页面遇到DNS解析或网络不可达，未完成网页许可文字的重核**；这一限制独立于已成功取得的官方营养API数值，不将“API可读”写成已经核验了网站全部使用条款。后续若重新发布数据汇编，应核对FDC当前使用说明并保留USDA来源。

## 程序边界

- 输入重量须为有限数值，范围为`0 < grams <= 5000`。
- `pending`条目不提供热量；无来源、缺具体参考或上下界不一致的已核验条目会报错。
- 每条范围必须等于其具体参考食品数值的最小/最大值。
- 接口返回参考食品名称、来源链接与局限说明，可与图像候选一起展示，但用户确认菜品后才决定采用哪个条目。
- 这些查表与算术检查不构成图像分类准确率或真实餐食热量测量实验。
